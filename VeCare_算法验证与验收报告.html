03

四步验收方案

每步给出详细步骤、验收标准（硬门）与注意事项。贯穿全程的第一原则：probe18k 档位一致性—— 使用 probe18k.wav 时，生成、录制、质检、标定、判定全链路必须带 --hw-f-max 18000。

STEP 1

探测音生成与文件验收（PC 侧，立即可做）

目标：确认写入 ESP32 的探测音文件本身无误——这是全链路的基准信号。

详细步骤

  1. 优先直接使用仓库随附的 probe18k.wav；如需更长时长再生成（SD 循环播放建议 300 s）：
$ python3 replay_audio.py --emit-probe probe18k.wav --seconds 300 --hw-f-max 18000
  1. 对文件做格式与频谱复核（ffprobe / wave 模块 + 频谱脚本）。

验收标准（硬门）

  • WAV 为 48 kHz / 单声道 / 16-bit PCM，样本总数 = 960 的整数倍（60 s = 28,800,000 样本）；
  • 再生成文件与分发文件逐字节一致（filecmp）；周期 960 样本（= 20 ms）；
  • 频谱：能量 98%+ 集中在 10.3–16.7 kHz，24 根载波峰电平差 ≤ 3 dB。

注意事项

  • 档位选择依据：头枕扬声器按功放 + 扬声器实测 −3 dB 上限选档——上限 ≥ 18 kHz 用 18k 档（载波顶 16.5 kHz，留 1.5 kHz 保护带），只有 ≥ 20 kHz 才用默认 20k 档；
  • 禁止任何重编码（MP3/AAC 重压、重采样、淡入淡出、归一化）——任何破坏 960 样本周期网格的操作都会毁掉帧同步。
STEP 2

播放链路验收——喇叭输出符合"标准工况"的手段

标准工况 = 数字域周期完整 + 电域无削波 + 声域频响达标，分四层逐级验证。

2a. 数字域（固件层）

  • ESP32-LyraT 固件必须以 DMA 循环缓冲且缓冲区长度为 960 的整数倍循环播放；ES8388 锁 48 kHz（MCLK 12.288 MHz，use_apll）；禁止软件逐块搬运引入间隔、禁止任何 SRC。板上 NS4150 与模拟输出通道禁用；
  • 验收手段：用 LyraT 自身 line-out → line-in 自录 40 s，跑下方命令。帧同步 match_ratio ≥ 12、周期 std < 0.2 样本、strict_ratio ≥ 0.99、无削波、无静音孔，即数字域合格。
$ python3 replay_audio.py loopback.wav --qc --hw-f-max 18000

2b. 电域（功放与接线）

  • TPA3116D2 为 D 类功放：确认输出 LC 滤波（典型 10 µH + 0.68 µF，截止 ~61 kHz，理论上远高于 16.5 kHz，但实测必须做——负载阻抗 / 布板会改变滤波响应）；增益旋钮设置不得使输出削波；
  • 验收手段：示波器 / 音频分析仪在扬声器端子测——播放 probe18k 时波形应为探测音的缩放副本，无削波平顶、无 400 kHz 开关残留超标；记录峰值留 3–6 dB 余量（对应录音峰值 ≤ −6 dBFS）；
  • 接线：ES8388 AUX IN（选通 IN2、关闭 ALC）、麦克风前置放大电路必须由汽车 12 V（点烟器）取电且功放最后上电、最先断电，防止上电爆音与数字地串音。

2c. 声域（关键——头枕扬声器带宽 + 传声链路频响）

  • 用测量麦克风 + 音频接口（或示波器 + 标准麦克风）对 TPA3116D2 → 头枕扬声器 → 空气 → 麦克风 整链做 8–24 kHz 扫频，再单独播 24 根载波单音（10.5–16.5 kHz，间隔约 261 Hz）；
  • 验收标准：10.5–16.5 kHz 内衰减 ≤ 10 dB，无死载波（某根载波低于其余 > 10 dB 即为死载波——会触发运行期剔除，削弱空间分集）；
  • 这是方案中"普通功放 / 扬声器在 20 kHz 以上快速滚降，必须扫频确认"的具体化：头枕扬声器多为中高频小单元，高频滚降点和盆架谐振需逐点确认；TPA3116D2 数据手册带宽虽标称至 20 kHz+，带载实测才算数。

2d. 声学布置对照

  • 头枕扬声器 → 座椅目标区域 ≈ 30–60 cm，避免 CIPP 下静默锥；车内驻波必然使各载波增益有差异（±5 dB 常见，属正常多径），QC 的"频带"项只对 > 10 dB 的死载波 WARN；
  • 电气串音对照：静默工况录 30 s（应无探测音、match_ratio ≈ 8），再正常播放对照——若静默时麦克风仍拾到串音，说明功放 / 麦克风供电耦合，须整改后再继续。
STEP 3

录制验收（SD 卡音频）

目标：录音满足 8 项质检硬指标，并通过平台级预检（比 run_wav 更严的门）。

详细步骤

  1. SD 卡写 WAV（48 kHz / 单声道 / 16-bit，24-bit 更佳），每段 ≥ 20 s（建议 30–60 s）；
  2. 拷回 PC 后先跑单项质检：
$ python3 replay_audio.py capture.wav --qc --hw-f-max 18000

验收标准（8 项质检硬指标）

质检项硬指标
帧同步match_ratio ≥ 12（9–12 为 WARN，提示信噪比低）
周期std < 0.2 样本 且 strict_ratio > 0.99（单时钟平台应接近 100%；2 ppm 漂移即达 99.4% 边界）
连续性无静音孔、削波样本 = 0
电平峰值留 3–6 dB 余量
时长 / 格式≥ 20 s；48 kHz 单声道

随后跑平台级预检（硬门逻辑，比 run_wav 严），要求能分离空车 / 有人、无死载波：

$ python3 tools/check_platform.py --empty empty1.wav empty2.wav --people p1.wav p2.wav --hw-f-max 18000

注意事项

  • run_wav 只对 FAIL 拒识、WARN 不阻断（如 4–10 ppm 漂移只 WARN）——平台验收请按上表硬门人工把关，不要只看最终能否出判决；
  • 严禁用手机 / 电脑播放探测音（跨设备时钟漂移：历史真机录音 strict 仅 0.48–0.86，全部被正确拒识）；严禁音频编辑器"打开–保存"（重采样 / 抖动破坏周期网格）；
  • 头枕扬声器发出的探测音是 10.5–16.5 kHz 高频噪声（接近可听上限），人耳闷、录音听感"安静"是正常的，不要据此调大增益到削波。
STEP 4

判定算法验收

目标：空车标定 → 有人闭环 → 统计指标，复现论文表 2 口径（论文基准 DR 98.8%、FAR 2.1%）。

详细步骤

  1. 空车标定（空车录两段：一段做基线，一段跑预检验证零误报）：
$ python3 -m core.calibration --wav empty.wav --start 1 --seconds 5 --hw-f-max 18000
  1. 有人闭环：单人于座椅静坐、正常呼吸、浅呼吸（模拟婴儿）各录 60 s，带真值 BPM：
$ python3 replay_audio.py person.wav --hw-f-max 18000 --calibration
  1. 统计：空车若干段 + 有人若干段，人工标注真值（有人 / 无人 / 时间戳 / BPM），计算 DR / FAR / AUC。

验收标准

  • 空车全程无 presence、无报警；
  • 有人：检出 ≤ 5 s 证据窗聚合 + 报警 ≤ 10 s（t = 0 起算，Euro NCAP 口径）；BPM 误差以自检精度为参照（闭环实测误差 ≤ 0.3 BPM 量级，真机以测得的呼吸带真值为准）；
  • 呼吸峰形：CSI 相位 ACF 在真实 BPM 处的峰应显著（有效 BPM 域 10–75，车内工况常用 10–60 检查）；
  • 干扰场景（开关车门、敲击）应被 V 形 ACF 特征识别为干扰，不产生持续 presence。

注意事项

  • 单目标数据严禁按多目标分组验收（方案 §9 红线）：多目标分组是对设计的破坏性错误——本实现每个头枕位是独立链路；
  • 浅呼吸（幅度小）与"人离开"的区分依赖空车基线——每次更换布置（座椅位置、麦克风点位、功放增益）后必须重新标定；
  • 不要用会议室等强反射 + 多人环境做验证，那不是该系统的设计工况。
04

红线与禁止事项汇总

来自平台搭建方案 §9 与本次实测发现，任何一条不满足即停止验收、先行整改。

1

档位贯穿

probe18k.wav ↔ --hw-f-max 18000 全链路一致（实测错配必拒识：match 5.4）。

2

探测音零改动

不重编码、不淡入淡出、不归一化——任何破坏 960 样本周期网格的处理都等于销毁基准信号。

3

同源时钟

播放与录制必须同守 ES8388 时钟（严禁外置声卡 / 手机）；SD 卡写卡阻塞导致 DMA 饿死是头号风险，缓冲 + 双缓冲必须验证（静默孔质检兜底）。

4

WARN 不是通过

--qc 出 WARN 时先修因（漂移 / 低信噪比 / 死载波）再继续；平台验收按 §03 硬门人工把关。

5

扫频定档

TPA3116D2 + 头枕扬声器的 10.5–16.5 kHz 频响必须逐载波实测，不信任数据手册标称。

6

单目标逐链路验收

多目标分组无效；空车基线随布置变更重标。

总体结论：代码侧（生成 → 同步 → CSI → 判定）经 88 项测试 + 全场景闭环 + 失效注入验证，准确性达标， 可直接支撑 ESP32-LyraT / TPA3116D2 平台验证论文原理；执行层按本报告 Step 1–4 逐层验收即可。
