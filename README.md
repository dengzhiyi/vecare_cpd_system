# VeCare CPD System

基于**统计声学感知（SAS, Statistical Acoustic Sensing）**的车内儿童存在检测（CPD, Child Presence Detection）功能样机。

复用/模拟车载扬声器与单麦克风：扬声器发出宽频探测信号，麦克风接收经座舱多径传播的 CSI（信道状态信息），通过 CSI 振幅的自相关统计同时检测**体动**与**呼吸**，并在**首个运动证据出现后 10 s 内**触发告警。附带实时 Web UI 与 JSONL 会话日志回放。

完整验证链路的图文总览见 [`VeCare_验证链路总览.html`](./VeCare_验证链路总览.html)（浏览器直接打开，无需起服务）：仿真输入是什么、实采如何接入、三条验证路径怎么跑、硬件到不了 20 kHz 时算法怎么改。

> 本项目为**功能样机**，用于验证 SAS 检测链路与交互流程，**不做量产适配**、**不做多目标区分**、**不做速度估计**，也**未做真实新生儿大规模验证**。

## 功能

- **SAS 声学前端（仿真）**：50 Hz CSI、24 个子载波（10.5–23.5 kHz），静态座舱多径 + 弱目标反射 + 胸腔呼吸位移 + 体动 + 噪声/振动突发。载波集由 `plan_band()` 按**硬件频响上限**推导，扬声器/麦克风到不了 23.5 kHz 时自动收窄（见「硬件带宽受限」）。
- **实采音频前端**：把已录好的 WAV 还原成同一套 CSI。周期性探测音（20 ms 一扫，扫频带随硬件上限伸缩）经匹配滤波定位帧起点，再用频域正则化均衡在探针自己的 DFT 网格上取载波，得到 `|H(f)|` 后喂给同一条流水线。反向还提供 `render_wav`：把仿真场景渲染成 WAV，用于在无硬件时闭环验证这条前端。
- **运行时载波健康门控**：校准期（前 5 s）统计每个载波的相对抖动，把比同类高一个数量级（探针无能量、谱除法退化成噪声/噪声）的载波剔出 DSP 输入，界面上仍保留其原始幅度——死载波是硬件问题，不该被算法掩盖。
- **运动通道（1 s 窗，高通已移除）**：对原始 CSI 振幅取 1 s 窗、去均值 + 去线性趋势，统计残差能量 `δ`；判决量为归一化能量比 `δ/δ₀`（`δ₀` 由启动校准的背景中位数估计）。同时计算**子载波一致性 κ**（残差在子载波维度的第一奇异值能量占比）与**干扰图样判据**（ACF 是否呈 V 形冲击尖峰）。三者同时满足才判为运动：`δ/δ₀ > θ_δ` 且 `κ ≥ θ_κ` 且非干扰帧。
- **呼吸通道（8 s 窗）**：子载波 ACF 按 `g(f) = ρ(f, τ = 1/Fs) = ρ(f, 20 ms)` 加权做最大比合并（MRC），权重取呼吸窗自身、**未经高通**的短时滞统计量；在 0.80–6.00 s 时滞区间（75–10 BPM）内按峰高/显著度/宽度筛选呼吸峰，抛物线插值得到 `τ_b`，`BPM = 60/τ_b`，再做**谐波下降**（若 `τ/2` 附近存在足够高的峰则判为谐波并下降一级）与中位数平滑。论文的「静止时才估呼吸」有条件放开：运动通道判为运动时，只要呼吸峰的位置与此前几次估计一致（±10%），仍输出呼吸率——否则安静录音（噪声底低）下胸廓自身的去趋势残差就会触发运动门控，**录得越干净反而越测不到呼吸**。
- **实时报警**：5 s 证据窗口内证据占比 ≥ 30% 确认存在；**响应预算 10 s 自首条证据起算**（而非自确认起算），倒计时归零即告警；证据断档超过 5 s 则开启新证据段并重置预算；确认呼吸后 15 s 无呼吸升级为呼吸暂停（APNEA）告警；支持确认静音（ACKED）。
- **Web UI**：实时监测、座舱声学动画、4 个 Canvas 图表（运动能量比 / BPM 趋势 / 合并 ACF / CSI 热力图）、事件流、真值对照（仅用于验证，检测链路不读取）。
- **日志回放**：JSONL 会话记录（`frames.jsonl` / `events.jsonl` / `meta.json`），支持播放、倍速、进度拖动、事件按仿真时间过滤与原始日志下载。

## 运行

依赖 Python 3.11+、numpy、scipy；测试需要 pytest。

```bash
pip install numpy scipy pytest

cd vecare_cpd_system
python server.py --port 8090
```

浏览器打开 `http://127.0.0.1:8090`，选择场景后点击「开始监测」，可调整灵敏度与 1–16× 倍速。

## 实采录音接入

检测链路不关心音频从哪来，只要求两件事：**录音里包含探测音**、**采样率够高**。仿真只是替这条链路生成媒体，实采把媒体换掉即可。

```bash
# 1. 生成探测音（录音时循环播放它）
python replay_audio.py --emit-probe probe.wav --seconds 300

# 2. 回放已录好的音频
python replay_audio.py capture.wav

# 3. 存成可回放会话，之后在 Web UI「日志回放」里看
python replay_audio.py capture.wav --save data/sessions

# 4. 没有硬件时验证这条链路本身
python replay_audio.py --selfcheck
```

### 音频格式

| 项 | 要求 | 说明 |
|---|---|---|
| 容器/编码 | WAV，PCM 整数 | 8/16/24/32-bit 都可；**浮点 WAV 与 mp3/aac/m4a 不支持**，需先转 16-bit PCM |
| 采样率 | **≥ 48 kHz** | 载波到 23.5 kHz，44.1 kHz 的 Nyquist 只有 22.05 kHz，会直接拒绝 |
| 声道 | 单声道优先，双声道自动下混 | 下混会削弱相位差，但对 `\|H(f)\|` 无影响 |
| 时长 | ≥ 20 s，建议 40 s 以上 | 前 5 s 用于背景校准，之后至少要有 15 s 以上的证据 |
| 增益 | 不削波，峰值留 3–6 dB 余量 | 削波在频域是宽带失真，会把 CSI 直接搞坏 |

### 录制时要注意

1. **必须播放探测音**。这是主动探测（active sensing），不是「录一段座舱声音」。没有探测音就没有 CSI，只有语音和路噪。探测音是 20 ms 周期的扫频，循环播放即可。
2. **关掉一切音频前处理**：降噪、回声消除、自动增益（AGC）、指向性波束成形。AGC 会让人为的幅度调制盖过呼吸引起的几百 ppm 变化；降噪会把 10 kHz 以上的探测音当噪声删掉。
3. **播放与录音的时钟要一致**。同一台设备最稳；跨设备允许缓慢漂移（帧同步按实测周期跟踪），但不能有重采样或变速——周期一变，20 ms 的帧率假设就破了。
4. **播放设备带宽**。实测：低通到 16 kHz 仍能检出（10.5–16 kHz 这一段载波还活着，MRC 会自动压低失效载波权重），低通到 12 kHz 就报「未找到探测音」。普通笔记本扬声器切在 20 kHz 左右可用，超声波喇叭更好。
5. **麦克风带宽 ≥ 24 kHz**。多数 MEMS/USB 麦克风可以，但通话耳麦往往在 16 kHz 就截止。
6. **前 5 s 车内应无人或完全静止**。校准期估计的是背景残差能量 `δ₀`；如果婴儿一开始就在里面动，`δ₀` 会被抬高，灵敏度随之下降。
7. **麦克风与座椅相对位置固定**，别手持。手抖在 10–30 cm/s 量级，正好落在论文指出的 J0 零点速度带附近，会让幅度响应失真。
8. **记下现场条件**：距离、座椅位置、车窗开闭、空调档位、是否有人说话。这些直接决定结果能不能复现。

### 输出怎么读

```
文件        capture.wav
采样率      48000 Hz      帧率  50.0 Hz（周期 960 采样）
时长/帧数   69.96 s / 3499 帧      补齐 0  空洞 0
载波        24 个 @ 10500–23500 Hz      探头裕量 -2.74 dB
电平        峰值 0.98  RMS 0.36438      削波样本 0
------------------------------------------------------------------
判定        检测到儿童 @ 14.0 s（呼吸证据）
告警        @ 19.7 s   原因 PRESENCE
响应时间    10.0 s（自首条证据起算）
呼吸率      24.0 BPM（11.9–25.3，n=566）
运动证据    88 帧 / 690      干扰抑制 0 帧      最大能量比 2.21
MRC 有效子载波 21.90 / 24
```

- `补齐/空洞`：探测音周期漏检的帧数与不可补齐的长断档。空洞多说明录音有丢帧或播放中断，呼吸率的时基会不准；
- `探头裕量`：最弱载波比最强载波低多少 dB，是探测音设计指标，与录音无关；
- `削波样本 > 0` 必须先解决，否则后面的数字没有意义。

### 常见失败

| 报错 / 现象 | 原因 | 处理 |
|---|---|---|
| `no probe repetition found ... need >= 8` | 录音里没有探测音，或被重采样/降噪破坏 | 确认播放了 `probe.wav`，关掉音频前处理 |
| `sample rate is 44100 Hz ... Record at 48 kHz` | 采样率不足 | 重录或用 48 kHz 设备录 |
| 检测到存在但 `呼吸率 未输出` | 载波几乎全是噪声（扬声器带宽不够），或证据来自运动通道 | 换带宽更宽的扬声器；`--sensitivity 1.5` 放宽 |
| 空车厢也告警 | 校准期不安静（车内有人说话/行驶中录） | 重录，前 5 s 保持静默 |
| 一直 `MONITORING` | 目标太远或反射太弱 | 缩短距离，或提高 `--sensitivity` |

### 闭合自检

`--selfcheck` 把七个仿真场景渲染成 WAV 再喂回检测链路，与直连仿真的结果对比。两边看的是同一个场景，所以**一旦不一致就是前端的问题，不是场景太难**：

```
场景                   存在(直连/回放)           告警(直连/回放)        BPM(真值/回放)         运动帧
empty                      —/—                 —/—               —/—         0/0
sleeping             15.4/15.7           24.0/24.2           18/18.1         0/0
active               14.3/14.0           19.8/19.7           24/24.0       68/88
apnea                15.0/14.5           19.8/19.7           20/20.2         4/9
newborn              15.4/14.3           24.0/22.8           30/30.0         0/0
stress                     —/—                 —/—               —/—       21/24
adult                16.3/16.5           25.0/25.0           14/14.1         0/0
```

判定与呼吸率在七个场景全部一致（`--snr 35` 与仿真器自身的 CSI 噪声水平相当）。加 `--hw-f-max 16000` 会在收窄的新频带上重跑同一套对照。

## 硬件带宽受限（18 kHz / 16 kHz）

论文的 10.5–23.5 kHz 假设了宽频换能器。车载球顶高音加 MEMS 麦克风常常只能到 18 kHz，通话级器件甚至只到 16 kHz。这件事**不能靠调阈值糊过去**，因为失效不是渐进的。

### 为什么硬撑 23.5 kHz 会崩

载波落在硬件滚降上时，该频点的探针功率接近零，谱除法变成 `噪声 / 噪声`。估算出的 `|H|` 不再有信号成分，只剩一条宽带随机序列。实测（空车厢、渲染 WAV 经 18 kHz 低通）：

| 载波位置 | 相对抖动 `std/mean` |
|---|---|
| 10.5–16.5 kHz（有效带内） | 0.013 |
| 21–22 kHz（滚降区） | 0.20 → 0.48 |

于是残差能量读到「运动」，MRC 权重读到「相关性」。**空车厢在 17.58 s 确认存在并告警**，BPM 还报出 12–13。这不是精度下降，是安全性崩塌。

### 设计期：从硬件上限反推频带

`plan_band(hw_f_max)` 按三条相互冲突的约束求解：

1. **离滚降要远**：载波带顶 `= min(23.5 kHz, 硬件上限 − 1.5 kHz)`。18 kHz 器件取 16.5 kHz。
2. **间隔要够做频率分集**：相邻载波需满足 `Δf × 多径时延展宽 ≳ 1`（9.2 ms 展宽下约 110 Hz），取 250 Hz 留余量。
3. **载波数要够**：MRC 靠它平均噪声，一致性检验也靠它估计秩一占比。

| 硬件上限 | 载波带 | 载波数 | 间隔 | 分集度 | 扫频带 |
|---|---|---|---|---|---|
| 无限制 | 10.5–23.5 kHz | 24 | 565 Hz | 5.20 | 9.8–23.9 kHz |
| 20 kHz | 10.5–18.5 kHz | 24 | 348 Hz | 3.20 | 9.8–19.2 kHz |
| **18 kHz** | 10.5–16.5 kHz | **24** | 261 Hz | 2.40 | 9.8–17.2 kHz |
| **16 kHz** | 10.5–14.5 kHz | **17** | 250 Hz | 2.30 | 9.8–15.2 kHz |
| 14 kHz | 10.5–12.5 kHz | 9 | 250 Hz | 2.30 | 9.8–13.2 kHz |

18 kHz 仍能保住 24 路（6 kHz 带宽），16 kHz 只能降到 17 路——**宁减载波数也不压间隔**：17 路仍能有效平均噪声，而 24 路挤在 174 Hz 间隔上会开始共享多径条纹，MRC 分集白拿。

扫频带同步收缩，因为向驱动发不出的频率注入能量，只会摊薄真正被用到的那些载波的 SNR。

**表里每一行的下限都是 10.5 kHz，它不是规划出来的**：目标器件的规格都是 10 kHz 高通，`F_LOW = 10.5 kHz` 本身已含 500 Hz 的 guard，所以只有频带顶部跟着硬件走。下限若也随带宽收缩，等于在两次运行之间换掉了参与平均的物理路径，呼吸通道的 ACF 噪声底标定会随之失效。

1.5 kHz 的顶部 guard 也反向验证过：16 kHz 下把它收到 800 / 400 Hz（载波增至 19 / 21 路）后，入睡场景 BPM MAE 反而从 0.249 升到 0.268 / 0.290，静息场景开始冒出 1–2 帧运动误判。瓶颈在呼吸信号的相干时间，不在载波数，所以保守的 guard 留着。

### 运行时：载波健康门控

规格书不可信（实际 -3 dB 点、麦克风开孔、车内吸声都会改变滚降），所以流水线在校准期（前 5 s）自己判断：算每个载波的相对抖动，剔除比同类高一个数量级的那批。

基准取**25 分位而非中位数**——一半频带死掉时中位数自己已经移进死载波里了。实测 18 kHz 上限下：中位数 0.11（阈值 0.34，一个都不剔），25 分位 0.028（阈值 0.084，准确剔掉 3 个）。

若存活载波不足一半，函数保留全部并让上层报出硬件异常，而不是悄悄在 3 个载波上继续跑。

### 实测：三种带宽的全场景指标

| 场景 | 24 载波（无限制） | 24 载波 @18 kHz | 17 载波 @16 kHz |
|---|---|---|---|
| 空车厢 | 不告警 / 0 帧 | 不告警 / 0 帧 | 不告警 / 0 帧 |
| 噪声振动 | 不告警 / 21 帧 | 不告警 / 23 帧 | 不告警 / 23 帧 |
| 入睡婴儿 | 23.98 s / 10.1 s | 23.98 s / 10.1 s | 23.98 s / 10.1 s |
| 活跃儿童 | 19.78 s / 10.0 s | 19.78 s / 10.0 s | 19.78 s / 10.0 s |
| 呼吸暂停 | 20.28 s / 10.0 s | 19.78 s / 10.0 s | 19.98 s / 10.1 s |
| 新生儿 | 23.98 s / 10.1 s | 23.98 s / 10.1 s | 23.98 s / 10.1 s |
| 成人 | 24.98 s / 10.1 s | 20.18 s / 10.1 s | 20.18 s / 10.0 s |
| BPM MAE（活跃/新生儿） | 1.96 / 0.58 | 2.55 / 0.51 | 2.68 / 0.82 |

（单元格为「告警时刻 / 响应时间」）

**三条硬判据在三种带宽下全部满足**：响应 10.0–10.1 s、空场景零误报、活跃儿童运动证据 67–72 帧。代价是 BPM 精度下降 30–40%（带宽窄 → 频率分集变少），以及 MRC 有效子载波数从 21.9 降到 15.1——这是物理上限，不是实现问题。

另外 κ 门控的阈值必须**随载波数缩放**。秩一能量占比在 N 路上有接近 1/N 的零假设，量化到 17 路时静窗中位数从 0.087 升到 0.113，原先固定的 `+0.015` 偏移让阈值落到 0.128，而持续噪声的峰值是 0.129——**一声关门就能被确认成儿童**。改用 `median + 5.5 × 稳健σ` 后，阈值在 24 路上仍是 0.115（行为不变），17 路上升到 0.142，噪声峰值 0.124 被挡、真实运动最弱帧 0.185 仍通过。

### 怎么用

```bash
# 已录的音频，按 16 kHz 硬件重新规划频带
python replay_audio.py capture.wav --hw-f-max 16000

# 导出配套探测音（必须先换探测音，否则扫频仍在往发不出的频段送能量）
python replay_audio.py --emit-probe probe16k.wav --seconds 300 --hw-f-max 16000

# 在该带宽下跑全场景闭合自检

```

## 模型说明

论文核心公式：

```
H(f, t) = Σ_r a_r(t) exp(-j2πf τ_r(t))
```

- 对每个子载波 CSI 振幅求 ACF：`ρ(f, τ)`；
- 运动统计量取**首个非零抽头**：`g(f) = ρ(f, τ = 1/Fs) = ρ(f, 20 ms)`。取 20 ms 而非更长的时滞，是因为 50 Hz 的 CSI 采样下 20 ms 对应相邻两帧，此时动态散射体的贡献最大、静态多径的贡献已被去趋势压掉；
- 运动**判决**不用 `g(f)` 本身，而用 1 s 窗去趋势残差能量比 `δ/δ₀`，并以子载波一致性 `κ` 与非干扰图样作为门控。原因是单看残差能量无法区分「有人动」与「空调噪声突变」，而 `κ` 把「对所有子载波同一延时的身体位移」和「各子载波独立的噪声」分开——前者相干、后者不相干；
- 呼吸检测对子载波 ACF 做 MRC 合并：`ρ̂(τ) = Σ w(f) ρ̃(f, τ)`，`w(f) ∝ g(f)`，`w(f)` 来自呼吸窗自身且**未经高通**（高通会把 20 ms 抽头的信噪比结构一起削掉）；
- 在 0.80–6.00 s 时滞区间内选峰，`BPM = 60/τ_b`，并对 `τ/2` 处的谐波做下降一级处理；
- 5 s 证据窗口占比 ≥ 30% 确认存在，**响应预算 10 s 自首条证据起算**；
- 呼吸通道的「静止」门控用**时滞一致性**替代：运动通道判为运动时，只要呼吸峰位置与此前估计相差 < 10% 仍输出 BPM。实测 25–70 dB 录制信噪比下，入睡婴儿始终输出 18.3–18.5 BPM（真值 18），不加这条在 45 dB 以上就会完全丢失呼吸率。

实采前端的三条式子（仿真链路不需要它们，但它们决定 WAV 能还原出什么）：

```
周期卷积:  R[k] = S[k] · H[k]        (L = 960 点 DFT, 20 ms 周期)
频谱除法:  Ĥ[k] = R[k]·S*[k] / (|S[k]|² + ε·max|S|²)
载波取值:  f_c 取在 DFT 网格上，Ĥ 直接取 bin，不插值
```

- 周期卷积成立的前提是舱内冲激响应短于 20 ms，因此每一帧可以独立切窗、独立反演；
- 载波**必须取在 DFT 网格上**。多径条纹的间距约 `1/Δτ ≈ 150 Hz`，而网格是 50 Hz，插值等于采样一个在两格之间来回振荡的量——实测即使零噪声也有 10 % 的幅度误差。取在网格上则精确到 1e-6（无噪）／0.5 %（40 dB）；
- 探测音扫频范围要比载波带**两侧各宽出 700 Hz**。若扫频起点正是 10.5 kHz，升余弦边缘会把能量削掉，最外侧两个载波的探针功率掉 23 dB，等效噪声放大 200 倍。加宽后带内平坦度从 23 dB 收紧到 3 dB；
- 硬件频响上限低于 23.5 kHz 时，**载波带、扫频带、载波数三者一起收**：载波带顶取 `上限 − 1.5 kHz`，载波数按 `带宽 / 250 Hz` 封顶，扫频带随之收窄（见「硬件带宽受限」）。这不是优化项——把载波放在滚降上会让该频点的 `|H|` 变回噪声，而残差能量与 MRC 权重无法把这种噪声和运动分开。

## 范围限制

- **实采链路未经真实硬件验证**。WAV 前端与检测链路已用「仿真 → WAV → 回放」闭环验证（七个场景判定一致），但从未接真实扬声器/麦克风录过音。真实座舱的混响长度、扬声器非线性、麦克风频响、多人活动都还没有数据；
- 帧同步假设座舱冲激响应短于 20 ms（6.9 m 行程）。大空间混响会绕回下一个周期造成混叠，车内不会；
- 不区分车内多目标，不估计目标速度；
- 阈值与场景参数基于仿真调校，未经真实新生儿大规模数据验证；
- **MRC 分集增益在本仿真器中不可验证**：仿真器的目标反射是频率平坦的（各子载波目标强度相同），`w(f)` 的分化只来自噪声实现，因此 `Neff` 虽已从等权情形的 23.48 降到 14.96–21.87，仍无法体现论文中「少数子载波承载有效信息」的真实分布。要验证这一点需要引入频率选择性的目标 RCS 与多径衰落；
- **带宽受限下的数字同样只有仿真支撑**。18/16 kHz 的结论来自「仿真信道 + 理想 6 阶低通」的带限模型，真实器件的滚降形状、通带纹波、单元谐振峰都没有建模——真实 16 kHz 器件的可用带宽很可能比这里的 14.5 kHz 更窄；
- 不包含量产级标定、车规认证与嵌入式移植。
